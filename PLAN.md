# Loom — Build Plan

A personal, local-first web UI for a local LLM. Five tabs: **Chat**, **Agents**, **Deep Research**, **Canvas**, **Memory**. Everything runs on localhost; no cloud, no telemetry.

This document is the source of truth for scope and sequencing. It is updated at the end of every phase.

---

## Operating rules

- Work in small, verifiable phases. **Stop after each phase**, summarize, give manual test steps, and wait for confirmation before continuing.
- Boring, well-supported libraries only. No abandoned packages.
- TypeScript strict mode. Lint + format enforced. No stray diagnostics.
- At a real architectural fork, **stop and ask** rather than guess.

---

## Locked stack decisions

| Concern                             | Choice                                                                                   | Notes                                                                                             |
| ----------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Framework                           | Next.js (App Router) + TypeScript                                                        | Single full-stack app on localhost                                                                |
| UI                                  | Tailwind CSS + shadcn/ui                                                                 | Dark mode default; dense, keyboard-friendly                                                       |
| Chat/agent streaming + tool calling | Vercel AI SDK (`ai`)                                                                     | OpenAI-compatible provider                                                                        |
| Canvas                              | React Flow (`@xyflow/react`)                                                             | + `dagre` for auto-layout                                                                         |
| DB                                  | **SQLite via Drizzle ORM** (`better-sqlite3`)                                            | Chosen over Prisma: lighter, TS-native, simple migrations via `drizzle-kit`. DB file in `./data/` |
| Migrations                          | `drizzle-kit`                                                                            | Never hand-edit the DB                                                                            |
| Vector search                       | `sqlite-vec` extension, **fallback to in-DB cosine** if the extension is painful to load | Embeddings from local LLM `/embeddings` endpoint                                                  |
| MCP                                 | `@modelcontextprotocol/sdk` (client)                                                     | stdio + SSE/HTTP transports                                                                       |
| LLM connection                      | OpenAI-compatible base URL, configurable                                                 | Default LM Studio `http://localhost:1234/v1`; Ollama via base URL swap only                       |

### Open decisions (revisit when the phase arrives)

- **Vector search**: ✅ DECIDED (Phase 2) — in-DB cosine in JS; embeddings stored as JSON `number[]`. Not `sqlite-vec`.
- **Embeddings model**: configurable in Settings; default to whatever the user sets (e.g. `nomic-embed-text` / `text-embedding-*`).

## Data model (sketch — refined per phase)

- `settings` — single-row key/value or typed columns: llmBaseUrl, llmModel, embeddingsModel, searxngUrl, etc.
- `conversations` — id, title, type (chat|agent|research), model override, timestamps.
- `messages` — id, conversationId, role, content, toolCalls JSON, createdAt.
- `canvases` — id, title, nodes JSON, edges JSON, timestamps.
- `mcp_servers` — id, name, transport, command/args/url, env JSON, enabled, status.
- `memories` — id, content, type, sourceConversationId, embedding (blob/json), pinned, createdAt.
- `research_reports` — id, conversationId, question, plan JSON, sources JSON, report markdown, createdAt.

### Phase 7 — Send to Canvas ✅ (complete — awaiting checkpoint confirmation)

LLM-driven session → JSON graph seeding from Chat/Agents/Research; render + save.

### Phase 11 — Experimental Agent (bidirectional goal convergence) ✅ (complete — awaiting checkpoint confirmation)

Off-plan, user-requested. A new **Experimental Agent** tab implementing a meet-in-the-middle, Dijkstra-flavored goal search: a **Forward agent** builds from the START state toward the GOAL, a **Backward agent** regresses from the GOAL toward the START, and a **Reconciler** detects when the two frontiers connect (a forward node's `established_facts` satisfy a backward node's `required_conditions`).

Built: extended the `conversations.type` enum with `"experimental"` (TS-only — no DB constraint) and a new `goal_runs` table (migration `0014`, persisting problem spec / start / goal / both frontiers / reconciler verdict / stitched bridge / status as JSON); client-safe `lib/bidirectional-config.ts` (shared `GoalNode`/`ReconcileResult`/`BridgeResult` types + round bounds); orchestrator `lib/bidirectional.ts` — an async-generator event stream that bootstraps the two roots (F0 start-facts + GOAL preconditions via a tolerant LLM call), then each round expands the **cheapest unexpanded** node on each side (forward + backward run in parallel), beam-prunes to bound frontier blow-up, reconciles, and stops on bridge / round-cap / stall; all three agents use `generateText` + tolerant JSON parsing (robust for local models). NDJSON streaming route `/api/bidirectional` (mirrors `/api/research`); `/experimental` surface — `ConversationList` (type `experimental`, "New goal search") + a live `BidirectionalView` (setup form: problem spec / start / goal / max-rounds; dual-column frontier viz with per-node facts/conditions/cost, the reconciler's best-pair score + unmet conditions + per-agent hints, and the final stitched START→…→GOAL bridge with total cost). Wired into the nav (`FlaskConical`), shared `SURFACE_PATH` revalidation, the memory-suggestion surface maps, and global Ctrl-K search (`experimental` category). The header also carries a **ContextMeter** (context-window usage from a synthetic transcript of the framing + frontiers + bridge) and a **Send to Editor** button (`runToMarkdown` → a new Editor document with the problem framing + final answer, best-effort RAG-indexed). When a **bridge is found the run auto-builds and opens a Canvas** of the whole search — both frontiers laid out START→GOAL with the taken path drawn in neon-green and the rest dimmed — via a deterministic (no-LLM) `runToCanvasGraph` + `createRunCanvas` and `sendRunToCanvasAction`; a manual **Send to Canvas** button covers past/stalled runs. typecheck/lint/build all green; runtime smoke-tested (`/experimental` 200 + empty state + sidebar, `/api/bidirectional` input validation) — the live forward/backward/reconciler loop needs a running model (user to verify).
